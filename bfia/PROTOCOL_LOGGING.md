# 原生 BFIA 算法日志与数值验收

日志来自算法进程的真实执行点。协议依据为仓库 `interconnection/interconnection/handshake/entry.proto` 及对应算法、密码协议族、数据 IO protobuf。这里的成功表示当前双方实现按该协议运行；第三方产品互操作认证需要另行对测。

## 产物

每个算法保留双方原始日志，不用摘要替代。`collect_protocol_audit.py` 生成：

- `protocol-events.jsonl`：实际结构化事件，含任务/追踪 ID、时间、序号、阶段和双方信息。
- `protocol-trace.md`：按阶段整理的可阅读记录。
- `protocol-validation.json`：阶段检查、消息关联和原日志 SHA256。
- 数值验收由独立参考计算生成 `numerical-validation.json`，与流程验收分开。

发送队列成功不等于接收成功。Python 消息仅记录字节数和 SHA256，用双方日志核对发送/接收；不记录载荷。C++ 握手记录 protobuf 版本、双方 rank、算法/安全算子/密码协议族/IO 参数，底层传输统计来自 YACL。算法内部已有运算阶段日志保留在原始日志。

## 应有流程与证据

| 阶段 | 证据 | 失败处理 |
| --- | --- | --- |
| 初始化与连接 | 真实监听地址、对端、传输模式、任务标识 | 初始化错误不得当作通信成功 |
| 数据准备 | 本方行列数、列选择、角色，不打印样本 | 无效输入失败退出 |
| 主动方发请求 | HandshakeRequest v2，算法/算子/密码协议族/IO 提案 | 不支持的版本或参数应拒绝 |
| 被动方协商与响应 | HandshakeResponse，error_code 与最终参数 | 非 OK 不得进入计算 |
| 主动方接受响应 | 接收响应、成功解包并采用协商值 | 不静默忽略不支持参数 |
| 安全计算 | 算法阶段、轮次、实际消息元数据 | 异常明确失败，不输出成功标志 |
| 输出 | 结果类型、接收方、维度、产物位置 | 秘密份额不得伪装成明文指标 |
| 链路收尾 | 待发消息排空、发送/接收统计、退出码 | 阶段缺失由验证器报错 |

C++ 严格验收设置 `BFIA_STRICT_PROTOCOL=1`：黑盒传输建立失败时不自动切换白盒。`start_transport=true` 使用本地黑盒转发器承载实际双容器通信；它不是第三方生产通信平台验收。

## 各算法数值含义

| 算法 | 关键阶段 | 输出及检查 |
| --- | --- | --- |
| ECDH-PSI | 曲线/哈希/编码/输出方协商，双方集合处理 | 与公开输入的精确集合交集比较 |
| SS-LR | SS/优化器/sigmoid/批次协商，安全训练 | 精确环份额重构参数，与同参数 SGD 对照；不以 Accuracy 单独判定 |
| SGB | PHE/密钥长度/轮数协商，加密梯度训练、预测 | 导出明确请求的验收概率，双方一致，重算 AUC；训练集指标不是泛化能力 |
| HE-WOE | PHE/分箱参数协商，加密标签统计、分箱计数 | 逐特征核验分箱计数、WOE 和 IV，明确空类别平滑规则 |
| SS-XGB | SS/树参数/特征数/标签方协商，安全直方图分裂、逐树更新 | 完整集成模型预测份额，重构概率，与同参数明文算法对照 |
| SS-Pearson | SS/IO 协商，中心化、协方差、标准化 | 按接收方重构的相关矩阵，与 NumPy 对照 |
| SS-VIF | SS/IO 协商，标准化、矩阵求逆 | 按接收方重构的 VIF，与相关矩阵逆的对角线对照 |
| SS-Compare | 比较算子、双方本地列索引、全局列与输出方协商 | 明确两列或均值模式，并与相同模式的参考逐行比较 |

`bfia-ring-share-v1` 保存整数环原值的十六进制及 ring_bits/fraction_bits/shape。只在授权的公开测试数据上，由 `validate_numerics.py --public-fixtures` 执行模加重构后解码；严禁先将各方份额转成低精度浮点再相加。

## 运行与判定

先运行原生双方算法，再调用对应验收器。流程 PASS、数值 PASS、第三方互操作认证是不同结论。完整日志不包含私钥、令牌、原始私有样本和份额值。测试环境当前使用的 TrustedFirstParty 三元组模式必须在证据中明确；它不构成生产安全性认证。
